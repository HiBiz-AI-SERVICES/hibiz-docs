The `ai-chat-server/services/` directory holds the server's shared service modules: SQL Server access, email sending, Gmail ingestion, one-time-password auth, currency conversion, and the LLM-backed conversation engine. Reach for this page when you need the exact export names, parameters, return shapes, and environment variables of a service before calling it from a route or another module.

Each service is a CommonJS module that exports plain functions via `module.exports`; there are no classes. Every module reads its secrets from `process.env` (loaded once via `dotenv`).

## Environment variables

All services are configured entirely through environment variables. The table below collects every variable read across the modules on this page.

| Variable | Used by | Required | Meaning |
|----------|---------|----------|---------|
| `DB_USER` | `db.js` | Yes | SQL Server login user |
| `DB_PASSWORD` | `db.js` | Yes | SQL Server login password |
| `DB_HOST` | `db.js` | Yes | RDS server host |
| `DB_NAME` | `db.js` | Yes | PROD database name (also DEV fallback) |
| `DB_DEV_NAME` | `db.js` | No | DEV database name; falls back to `DB_NAME` |
| `SMTP_PASS` | `emailClient.js` | Yes | Gmail SMTP app password; `getTransporter()` throws if unset |
| `GOOGLE_CLIENT_ID` | `gmailClient.js` | Yes | Google OAuth2 client ID |
| `GOOGLE_CLIENT_SECRET` | `gmailClient.js` | Yes | Google OAuth2 client secret |
| `GOOGLE_REDIRECT_URI` | `gmailClient.js` | Yes | OAuth2 redirect URI |

<Note>
`emailClient.js` hardcodes the SMTP user (`support@hibiz.dev`), the `From` header (`HiBiz AI <support@hibiz.dev>`), and the host (`smtp.gmail.com:587`). Only the password comes from the environment.
</Note>

## `db.js` — SQL Server access

Manages `mssql` connection pools to AWS RDS SQL Server and exposes query helpers. Connections are lazily created and cached: `connectToDatabase()` returns a single shared PROD pool, `getDevPool()` a single shared DEV pool. `encrypt: true` and `trustServerCertificate: true` are set for AWS (not Azure); `requestTimeout` is 120000 ms for long report queries.

### Exports

| Function | Signature | Returns |
|----------|-----------|---------|
| `connectToDatabase` | `() => Promise<pool>` | Cached PROD `mssql` connection pool |
| `getDevPool` | `() => Promise<pool>` | Cached DEV connection pool (uses `DB_DEV_NAME`) |
| `sql` | (re-exported `mssql` module) | The `mssql` namespace, for `sql.Int`, `sql.Date`, etc. |
| `fillRequiredFields` | `(query, requiredFields?) => object` | Deep-cloned query with time-preset placeholders replaced by `Date`s |
| `getStoresForClient` | `(clientId) => Promise<Store[]>` | `recordset` of `{ StoreId, Name, Location }` |
| `getEmployeesForClient` | `(clientId) => Promise<string[]>` | Distinct non-empty `EmployeeName` values, alphabetically |
| `insertWeeklyKpi` | `({ clientId, storeId, StartDate, EndDate, salesKpi, joinsKpi }) => Promise<void>` | Upserts a `dbo.Kpi` row (MERGE) |
| `runDynamicQuery` | `({ query?, collection?, rawSQL?, clientId?, queryParams? }) => Promise<object>` | Query result rows or a `{ message }` object |

### `runDynamicQuery(options)`

Executes either a raw SQL string or a generated `SELECT` against a table, binding parameters and auto-binding any `@Param` referenced in the SQL but missing from `queryParams` (bound as `NULL` with a warning).

| Field | Type | Required | Meaning |
|-------|------|----------|---------|
| `query` | object | No | Column→value map turned into a `WHERE key='val' AND …` clause when `rawSQL` is not given. Defaults to `{}` (→ `WHERE 1=1`) |
| `collection` | string | No | Table name under `dbo.` for the generated query. Defaults to `'Transactions'` |
| `rawSQL` | string \| null | No | Full SQL to run verbatim; takes precedence over `query`/`collection` |
| `clientId` | number \| null | No | If set and `queryParams.ClientId` is absent, injected as `ClientId` (parsed to int) |
| `queryParams` | object | No | Named parameters bound via `request.input(key, val)`. Defaults to `{}` |

Returns `{ message: 'No results found.', collection }` when the recordset is empty; otherwise returns the query result (rows plus derived aggregation/group-by metadata).

<Warning>
The generated-query path interpolates `query` values directly into the SQL string (`${key}='${val}'`) and is **not** parameterized — only the `rawSQL`/`queryParams` path uses bound parameters. Do not pass untrusted input through the `query` object.
</Warning>

### `fillRequiredFields(query, requiredFields)`

Deep-clones `query` and, only when `requiredFields.length` is truthy, replaces string values matching a known preset key with a computed `Date`. Recognized preset keys: `startOfToday`, `endOfToday`, `startOfLastMonth`, `endOfLastMonth`, `startOfLastWeek`, `endOfLastWeek`.

## `emailClient.js` — transactional email

Sends mail through a pooled Gmail SMTP transport. The `nodemailer` transporter is created lazily on first use (`pool: true`, `maxConnections: 5`) and reused thereafter.

| Function | Signature | Returns |
|----------|-----------|---------|
| `sendEmail` | `({ to, subject, text, html }) => Promise<info>` | Nodemailer `info` object (includes `messageId`) |

| Field | Type | Required | Meaning |
|-------|------|----------|---------|
| `to` | string | Yes | Recipient address |
| `subject` | string | Yes | Subject line |
| `text` | string | No | Plain-text body |
| `html` | string | No | HTML body |

The `from` field is fixed to `HiBiz AI <support@hibiz.dev>` and cannot be overridden per call.

## `otp.js` — one-time-password auth

Issues and validates 6-digit email OTPs backed by the `dbo.OtpCodes` table. Codes are SHA-256 hashed at rest, expire after **10 minutes** (`OTP_TTL_MS`), and allow at most **3 attempts** (`MAX_ATTEMPTS`) before being consumed. Comparison uses `crypto.timingSafeEqual` to avoid timing leaks.

| Function | Signature | Returns |
|----------|-----------|---------|
| `createOtpForUser` | `(platformUserId) => Promise<{ otp }>` | The plaintext OTP (marks prior unused codes as used, inserts the new hash) |
| `validateOtp` | `(platformUserId, submittedOtp) => Promise<{ valid, reason? }>` | Validation result |
| `sendOtpEmail` | `(toEmail, otp) => Promise<void>` | Sends the Hebrew RTL OTP email via `sendEmail` |

### `validateOtp` result

Selects the newest unused, unexpired code, increments its attempt count, and resolves as follows:

| `valid` | `reason` | Condition |
|---------|----------|-----------|
| `false` | `no_active_otp` | No unused, unexpired code exists |
| `false` | `max_attempts` | Attempt count exceeded 3 (code is marked used) |
| `false` | `invalid_code` | Hash mismatch |
| `true` | — | Match; code is marked used |

## `gmailClient.js` — Gmail OAuth & ingestion

Wraps `googleapis` to run the Gmail read-only OAuth2 flow and pull inbox messages. Every function builds a fresh `google.auth.OAuth2` client from the `GOOGLE_*` env vars; the requested scope is `https://www.googleapis.com/auth/gmail.readonly`.

| Function | Signature | Returns |
|----------|-----------|---------|
| `getAuthUrl` | `(platformUserId) => string` | Consent URL (`access_type: 'offline'`, `prompt: 'consent'`, `state` = user id) |
| `exchangeCode` | `(code) => Promise<tokens>` | OAuth2 token set from an authorization code |
| `getGmailAddress` | `(tokens) => Promise<string>` | The authenticated account's email address |
| `getEmails` | `(refreshToken, maxResults?, pageToken?) => Promise<{ emails, nextPageToken }>` | Inbox message metadata list |
| `getEmailBody` | `(refreshToken, messageId) => Promise<object>` | Full message with decoded body + attachments |
| `getAttachmentData` | `(refreshToken, messageId, attachmentId) => Promise<string>` | Base64 (converted from base64url) attachment data |

### `getEmails`

Lists `INBOX` messages and fetches per-message metadata headers. `maxResults` defaults to `20`, `pageToken` defaults to `null`. Each item in `emails` is `{ id, subject, from, date, snippet }`; `nextPageToken` is `null` when there are no more pages.

### `getEmailBody`

Fetches the `full` message and walks the MIME parts to extract the first `text/plain` body (base64-decoded) and any file attachments. Returns:

| Field | Type | Meaning |
|-------|------|---------|
| `id` | string | Message id |
| `subject` / `from` / `date` | string | Header values (empty string if absent) |
| `snippet` | string | Gmail snippet |
| `body` | string | Decoded plain-text body |
| `attachments` | array | `{ attachmentId, filename, mimeType, size }` per attachment |

## `currencyConverter.js` — exchange rates

Fetches historical currency-to-ILS rates from the free Frankfurter API (ECB data, no key). Results are memoized in-process per `currency:date` key.

| Function | Signature | Returns |
|----------|-----------|---------|
| `getIlsRate` | `(currency, date?) => Promise<number \| null>` | ILS rate (1 unit = X ILS), or `null` |

| Parameter | Type | Required | Meaning |
|-----------|------|----------|---------|
| `currency` | string | Yes | Currency code, e.g. `'EUR'`, `'USD'` (upper-cased internally) |
| `date` | string | No | `YYYY-MM-DD`; defaults to today (UTC-sliced) |

Returns `null` when the currency is already ILS (`ILS`, `NIS`, `₪`), when the input is empty, or when the request fails or returns no `rates.ILS` (the failure is logged as a warning, not thrown). The HTTP request has a 5000 ms timeout.

## `conversationEngine.js` — conversation intelligence

The LLM-backed intelligence layer for interpreting user messages before data retrieval; it manages memory/state and calls Bedrock for analysis. It depends on `db.js` (`connectToDatabase`, `sql`) and `llm/bedrockClient.js` (`callBedrock`).

### `getDateContext(isHebrew)`

Returns a preformatted, human-readable block of resolved date ranges (today, yesterday, this/last week, this/last month, last 7/30 days, plus locale) for injection into the analysis prompt.

| Parameter | Type | Required | Meaning |
|-----------|------|----------|---------|
| `isHebrew` | boolean | Yes | Selects locale `he` (`Asia/Jerusalem`, week starts Sunday) or `en` (`America/New_York`, week starts Monday) |

Results are cached per locale (`he` / `en`) for the current calendar day and recomputed when the date rolls over.

<Info>
The date context exists **only** to resolve time expressions the user explicitly states. Per the analysis system prompt, it is never a source of default time values — a query needing a time range with none supplied must trigger clarification rather than defaulting to "today."
</Info>

The module also defines `ANALYSIS_SYSTEM_PROMPT`, the system prompt driving message interpretation. It instructs the model to decide `needsSql`, detect missing required context (`time_range` / `entity` / `scope`) into `needsClarification` with a `clarificationQuestion`, and handle pending-clarification follow-ups (`is_clarification_response`, merging `partialState` and building an `enhancedMessage`).
