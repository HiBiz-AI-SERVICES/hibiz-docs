The data layer wraps Microsoft SQL Server (AWS RDS) through the `mssql` driver, exposing lazily-initialized connection pools and a set of parameterized query helpers. Reach for this page when you need the exact signature, parameters, and return shape of a pool accessor or query function — or the connection config and safety constraints that govern them.

Database access is provided by a single module:

| Module | Language | Exports | Purpose |
|--------|----------|---------|---------|
| `ai-chat-server/services/db.js` | JavaScript | pool accessors + query helpers | PROD/DEV pools and the chat server's data-access functions |

The module reads connection settings from environment variables via `dotenv` and never hardcodes credentials.

## Connection configuration

Connection settings are assembled from environment variables at module load.

| Variable | Meaning |
|----------|---------|
| `DB_USER` | SQL login user |
| `DB_PASSWORD` | SQL login password |
| `DB_HOST` | Server host |
| `DB_NAME` | Database name (PROD) |
| `DB_DEV_NAME` | DEV database name; falls back to `DB_NAME` if unset |

The `options` are set to `encrypt: true`, `trustServerCertificate: true`, `enableArithAbort: true` — required for AWS RDS SSL connections (note: `trustServerCertificate` is `true` for AWS, unlike Azure).

The services pools set `requestTimeout: 120000` (2 minutes) to allow long-running report queries.

## Chat server pools

The services module maintains two separate module-level pools — one for production, one for development — each initialized on first use.

| Function | Signature | Behavior |
|----------|-----------|----------|
| `connectToDatabase()` | `() => Promise<sql.ConnectionPool>` | Returns the cached PROD pool, creating it via `sql.connect(config)` on first call. Logs and re-throws on connection failure. Preferred accessor for PROD queries. |
| `getDevPool()` | `() => Promise<sql.ConnectionPool>` | Returns the cached DEV pool, creating it via `new sql.ConnectionPool(devConfig).connect()`. Uses `DB_DEV_NAME` (falling back to `DB_NAME`). |

<Note>
Some helpers below call `sql.connect(config)` directly instead of `connectToDatabase()`. `sql.connect` returns the global shared pool, so this is functionally equivalent to using the cached PROD pool.
</Note>

## Query utilities

All query helpers use parameterized inputs (`request.input(...)`) rather than string interpolation of user values.

### `fillRequiredFields(query, requiredFields = [])`

Replaces named time-preset placeholder strings in a query object with concrete `Date` values, returning a deep clone. Used to materialize relative dates for prepared queries.

| Parameter | Type | Required | Meaning |
|-----------|------|----------|---------|
| `query` | object | yes | Query object, deep-cloned before mutation |
| `requiredFields` | array | no (default `[]`) | If empty, the clone is returned untouched; otherwise placeholders are replaced |

Recognized placeholder strings (any string value equal to one of these keys is swapped for the corresponding `Date`):

| Placeholder | Resolves to |
|-------------|-------------|
| `startOfToday` | Midnight today |
| `endOfToday` | Midnight tomorrow |
| `startOfLastMonth` | First day of previous month |
| `endOfLastMonth` | Last moment of previous month |
| `startOfLastWeek` | Start of last week |
| `endOfLastWeek` | End of last week (`23:59:59.999`) |

**Returns:** a new query object with placeholders replaced (or an untouched clone when `requiredFields` is empty).

### `getStoresForClient(clientId)`

Returns the stores belonging to a client.

| Parameter | Type | Required | Meaning |
|-----------|------|----------|---------|
| `clientId` | int | yes | Bound as `@ClientId` (`sql.Int`) |

Queries `dbo.Stores WHERE ClientId = @ClientId`. **Returns:** `result.recordset` — an array of `{ StoreId, Name, Location }` rows.

### `getEmployeesForClient(clientId)`

Returns the distinct, non-blank employee names scheduled for a client.

| Parameter | Type | Required | Meaning |
|-----------|------|----------|---------|
| `clientId` | int | yes | Bound as `@ClientId` (`sql.Int`) |

Queries `dbo.WorkSchedule` for distinct `EmployeeName`, excluding NULL and whitespace-only values, ordered by name. **Returns:** an array of employee-name strings (the `recordset` mapped to `row.EmployeeName`).

### `runDynamicQuery({ ... })`

Executes a dynamic query against SQL Server, either from a raw SQL string or by building a `SELECT` from a filter object, with automatic parameter binding.

| Field | Type | Required | Default | Meaning |
|-------|------|----------|---------|---------|
| `query` | object | no | `{}` | Key/value filters; each becomes `key='val'` in a `WHERE` clause when `rawSQL` is not provided |
| `collection` | string | no | `'Transactions'` | Target table; query is built as `SELECT * FROM dbo.<collection>` |
| `rawSQL` | string | no | `null` | If set, executed directly instead of building from `query` |
| `clientId` | int | no | `null` | If set and not already present, added to `queryParams.ClientId` |
| `queryParams` | object | no | `{}` | Named parameters bound via `request.input(key, val)` |

Binding behavior:
- Every entry in `queryParams` is bound by name.
- Any `@ParamName` referenced in the SQL but absent from `queryParams` is bound to `NULL` (with a warning logged).
- When `rawSQL` is omitted, the `WHERE` clause is joined with `AND`, defaulting to `1=1` when `query` is empty.

**Returns:** when the recordset is empty, `{ message: 'No results found.', collection }`; otherwise the result rows (`result.recordset`), with aggregation/grouping detected from the SQL for downstream shaping.

<Warning>
In `runDynamicQuery`, filter values from `query` are interpolated directly into the SQL string (`` `${key}='${val}'` ``) rather than bound as parameters. Only pass trusted keys/values through `query`; prefer `rawSQL` with `queryParams` for anything derived from user input.
</Warning>
